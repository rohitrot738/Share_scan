# बड़े पैसे की चाल — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** हर शाम NSE के delivery, deal और promoter data से हर शेयर के चार signal, एक 0–100 score और हर signal का
एक साल का track record बनाना, और app में section, stock-detail card, list mark, filter और alerts में दिखाना।

**Architecture:** एक अलग शाम का GitHub workflow (`bigmoney/`, Python) NSE की archive files पढ़कर एक store और
app की file (`big-money.json.gz`) `cr360-data` release में रखता है। App उसे `Cr360Repository` की तरह लाता है,
`BigMoneyBook` (शुद्ध Kotlin) पढ़ता है, और UI उसी book से बनता है।

**Tech Stack:** Python 3.11 (standard library + `cr360.build_app_cache` के helpers), pytest; Kotlin, Android
views, WorkManager, JUnit।

**Spec:** `docs/superpowers/specs/2026-11-05-big-money-design.md`

## Global Constraints

- Thresholds (spec से, बिल्कुल यही): spike `1.8`, calm `±2%`, min volume `100000`, min sessions `15` of `20`,
  churn volume `4.0×`, churn delivery `< 20`, deals window `30` sessions, streak `2+` deal days, circular `5`
  sessions, promoter window `90` days, record horizon `10` sessions, record min cases `30`, score-60 record।
- Score parts: spike 0–30 (1.0×→3.0× linear), build 0–20 (5-sess/20-sess 1.0×→1.5×), deals 0–25 (net ÷ 20-sess
  avg daily volume, 0→1 day; streak ⇒ full), promoter 0–25 (₹0→₹5 crore), churn −30, net selling subtracts on the
  same scale; total clamped 0–100.
- Series counted: `EQ`, `SM` only। Promoter: category `Promoters`/`Promoter Group`, mode `Market Purchase`/
  `Market Sale` only; dates after today dropped।
- NSE bot checks are never bypassed: plain `http_get` with `BROWSER_UA`, as `cr360/build_app_cache.py` does।
- Workflow: 13:45, 15:45, 18:45 UTC every day (19:15, 21:15, 00:15 IST; weekends too, for a Budget-day or Muhurat session); a session already in the store does nothing।
- Alerts: data by 22:30 IST ⇒ that evening (from 19:00), later ⇒ next morning 08:00–09:15 IST; once per session।
- Every user-visible string in all 12 `values*` folders (Hinglish default `values`)। CLAUDE.md: changelog entry
  (previous top entry stamped `1.2.144`), beginner's guide part with a 360px JPEG screenshot, glossary, FAQ,
  contents and Menu list in step।
- Commits end with the session's Co-Authored-By and Claude-Session lines; no model names।

## Review Focus

1. **NSE file not out yet / holiday / broken file** — the job must not publish a thin or empty app file, and the
   app keeps its old copy → `test_build_skips_when_no_new_session`, `test_build_refuses_thin_file`,
   `BigMoneyBookTest.truncatedFileReadsAsNull`।
2. **A stock with gaps** (suspended, newly listed, moved to BE) → under 15 of 20 sessions means no
   accumulation/churn, no crash on `None` → `test_accumulation_needs_15_sessions`, `test_gaps_are_none`।
3. **Bad filing dates** (`3034-03-05`) and non-market modes → ignored → `test_promoter_net_rules`।
4. **Repeated notifications** — the worker runs every 15 minutes, and deal/promoter flags last 30/90 days → one
   alert per session, deal/promoter only when new → `BigMoneyAlertsTest`।
5. **Tap on a listed stock missing from the latest scan** → a message, not a crash → handled in `MainActivity`
   (emulator check in Task 9)।

### Task 2: Signals, deal and promoter net, score

**Files:** Create `bigmoney/rules.py`; Test `tests/test_big_money.py`

  `accumulation(days: list[Day]) -> bool`; `churn(days: list[Day]) -> bool` (last element is today, the 20 before
  it the average); `ratios(days) -> Ratios(spike, build, volume, change)` (each `float|None`);

  (parts in order spike, build, deals, promoter, churn, selling); `flags(...) -> list[str]` of
